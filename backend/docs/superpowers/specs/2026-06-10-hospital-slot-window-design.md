# 병원 예약 슬롯 30일 윈도우 설계

## 목표

`hospital_available_slot`을 병원별 하루 30분 슬롯 기준으로 관리하되, 무한정 적재하지 않고 항상 앞으로 30일치만 유지하는 운영 방식을 정의한다.

## 전제

- 병원당 의사는 1명
- 병원의 예약 가능 시간이 곧 의사의 예약 가능 시간
- 슬롯 단위는 30분
- 슬롯 테이블은 `hospital_available_slot`
- 슬롯 row는 유지하고 `is_available` 상태값으로 예약 가능 여부를 관리한다

## 핵심 설계

### 1. 슬롯 저장 단위

슬롯은 `available_at DATETIME` 단일 값으로 저장한다.

즉, 날짜 컬럼과 시간 컬럼을 따로 두지 않고 아래처럼 저장한다.

- `2026-06-10 09:00:00`
- `2026-06-10 09:30:00`
- `2026-06-10 10:00:00`

각 row는 “병원 1개 + 특정 날짜의 특정 30분 시간대 1개”를 의미한다.

### 2. 유지 범위

슬롯은 항상 **오늘 기준 앞으로 30일치만 유지**한다.

예:

- 오늘이 `2026-06-10`이면
- `2026-06-10 00:00:00` 이후부터
- `2026-07-09 23:59:59` 범위까지만 유지

즉, 과거 슬롯은 남기지 않고 정리하며, 너무 먼 미래 슬롯도 미리 전부 만들지 않는다.

## 데이터 규모 예시

### 병원 1개 기준

가정:

- 하루 운영 슬롯 16개
- 30일 유지

계산:

- `16 x 30 = 480 row`

즉 병원 1개당 30일 운영 창에서는 대략 480개의 슬롯 row를 가진다.

### 병원 100개 기준

- `100 x 16 x 30 = 48,000 row`

이 정도는 일반적인 관계형 DB에서 충분히 관리 가능한 범위로 본다.

## 테이블 구조

테이블명:

- `hospital_available_slot`

컬럼:

- `slot_id` `BIGINT` PK
- `hospital_id` `BIGINT` FK
- `available_at` `DATETIME`
- `is_available` `BOOLEAN`
- `created_at` `TIMESTAMP`
- `updated_at` `TIMESTAMP`

권장 제약:

- `(hospital_id, available_at)` 유니크

## 슬롯 운영 방식

### 1. 초기 생성

병원별로 오늘부터 30일치 슬롯을 생성한다.

예:

- 병원 1번
- 운영 시간 `09:00 ~ 18:00`
- 점심시간 `13:00 ~ 14:00`

그러면 하루마다 아래 같은 슬롯을 만든다.

- `09:00`
- `09:30`
- `10:00`
- ...
- `12:30`
- `14:00`
- `14:30`
- ...
- `17:30`

초기 상태는 `is_available = true`다.

### 2. 예약 생성

예약 요청이 오면:

1. `hospital_id + reserved_at` 슬롯 row 조회
2. `is_available = true`인지 확인
3. 예약 성공 시 해당 슬롯을 `false`로 변경

### 3. 예약 취소

예약 취소가 허용되는 시점에는:

1. 해당 예약의 `hospital_id + reserved_at` 확인
2. 대응 슬롯을 찾아 `is_available = true`로 복구

### 4. 일일 정리

매일 한 번 아래 작업을 수행한다.

1. 현재 시각보다 과거인 슬롯 삭제 또는 보관 정책 적용
2. 30일 창이 유지되도록 가장 뒤의 하루 슬롯 새로 추가

즉, 매일:

- 오래된 1일치 제거
- 새로운 1일치 추가

형태로 30일 창을 유지한다.

## 조회 및 검증 방식

예약 생성 검증은 아래 기준으로 한다.

```sql
SELECT *
FROM hospital_available_slot
WHERE hospital_id = :hospitalId
  AND available_at = :reservedAt;
```

검증 규칙:

- row가 없으면 예약 불가
- row는 있지만 `is_available = false`면 예약 불가
- row가 있고 `is_available = true`면 예약 가능

## 장점

- 날짜/시간 조합을 `DATETIME` 하나로 단순화할 수 있다
- 슬롯 row를 삭제하지 않고 상태만 바꿔 운영할 수 있다
- 예약 취소 복구가 쉽다
- 30일 창만 유지하므로 데이터 양이 통제 가능하다
- 병원별 운영시간/휴게시간 정책을 반영해 슬롯 생성 규칙을 확장하기 쉽다

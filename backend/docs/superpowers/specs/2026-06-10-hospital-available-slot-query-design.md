# 병원 예약 가능 시간 조회 API 설계

## 목표

특정 병원과 특정 날짜를 기준으로 30분 단위 예약 슬롯 목록을 조회하는 API를 정의한다.

## 범위

- 포함
  - `GET /hospital/{hospital_id}/available-slots`
  - 요청값 `hospital_id`, `date`
  - 해당 날짜의 슬롯 목록 반환
  - 각 슬롯의 예약 가능 여부 반환
  - 관련 테스트 및 문서 반영
- 제외
  - 여러 날짜 동시 조회
  - 병원 운영 정보 추가 반환
  - 슬롯 생성 배치 로직 변경
  - 에이전트 오케스트레이션 API

## 설계 선택

### 선택안

특정 날짜의 전체 슬롯을 반환하고, 각 슬롯마다 `is_available` 값을 함께 내려준다.

이 방식을 선택한 이유:

- 에이전트가 가능한 시간과 불가능한 시간을 한 번에 판단할 수 있다
- 예약 생성 전 후보 시간 제안에 바로 사용할 수 있다
- 슬롯 조회 책임과 예약 생성 책임을 분리할 수 있다

### 비교한 대안

1. 가능한 슬롯만 반환
   - 응답은 단순하지만, 불가능한 시간 정보를 잃는다
2. 하루 전체 슬롯 + `is_available` 반환
   - 현재 선택안
3. 슬롯과 병원 운영 정보 동시 반환
   - 기존 병원 목록 API 책임과 겹친다

## API 계약

### 요청

- 메서드: `GET`
- 경로: `/hospital/{hospital_id}/available-slots`
- 인증: `USER`
- 쿼리 파라미터
  - `date`: `yyyy-MM-dd`

예시:

```http
GET /hospital/1/available-slots?date=2026-06-11
```

### 응답

성공 시:

```json
{
  "success": true,
  "code": "20000",
  "message": "요청에 성공했습니다.",
  "data": {
    "hospital_id": 1,
    "date": "2026-06-11",
    "items": [
      {
        "available_at": "2026-06-11T09:00:00",
        "is_available": true
      },
      {
        "available_at": "2026-06-11T09:30:00",
        "is_available": true
      },
      {
        "available_at": "2026-06-11T10:00:00",
        "is_available": false
      }
    ]
  }
}
```

## 처리 흐름

1. `hospital_id`로 병원 존재 여부를 확인한다
2. 요청 `date`의 하루 범위를 계산한다
3. `hospital_id + date` 범위의 슬롯을 조회한다
4. 시간 오름차순으로 정렬해 반환한다
5. DTO가 응답 변환을 담당한다

## 예외 후보

최소 예외 후보:

- 병원 없음
- 날짜 형식 오류
- 비인증 사용자

현재 1차 범위에서는 날짜 범위 내 슬롯이 없더라도 빈 목록을 반환한다.

## 테스트 전략

### RED

- 컨트롤러 테스트
  - 인증 사용자 조회 성공
  - 비인증 사용자 실패
- 서비스 테스트
  - 특정 병원의 특정 날짜 슬롯을 시간순으로 반환
  - 병원이 없으면 예외
  - 슬롯이 없으면 빈 목록 반환
- DTO 테스트
  - 엔티티 목록이 응답 DTO로 올바르게 변환

### GREEN

테스트를 통과시키는 최소 구현만 추가한다.

### REFACTOR

날짜 범위 계산과 DTO 변환이 읽기 쉽게 유지되는 선에서만 정리한다.

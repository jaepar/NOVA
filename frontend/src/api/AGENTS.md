# API 레이어 AGENTS 가이드

## 1) 실행 명령
- 프론트 빌드 검증: `cd ..\\.. && pnpm build`

제약:
- API 호출은 반드시 `client.ts`의 `apiClient`를 사용한다.
- 엔드포인트 모듈에서 raw `axios` 인스턴스를 새로 만들지 않는다.

## 2) 모듈 컨텍스트
- `src/api`는 프론트엔드 API 접근 경계다.
- 전송 계층(헤더, 에러, 로깅) 공통 처리를 중앙화한다.

## 3) 필수 규칙
- 엔드포인트 래퍼에 금액 확정/원장 판단 로직을 넣지 않는다.
- 인증 헤더 주입은 `client.ts` 인터셉터 단일 책임으로 유지한다.
- 시크릿/고정 자격증명을 코드에 저장하지 않는다.

## 4) 구현 규칙
- 엔드포인트 함수마다 요청/응답 DTO 타입을 명시한다.
- envelope 구조에서는 `response.data.data`를 일관되게 반환한다.
- 신규 엔드포인트는 `src/api/index.ts`에 export를 추가한다.
- UI 상태 변경/라우팅 로직을 API 모듈에 넣지 않는다.

## 5) 타입 규칙
- 공통 타입 사용:
  - `ApiResponse<T>`
  - `PaginatedResponse<T>`
  - `ApiError`
- 광범위한 `any` 사용 금지

## 6) 검증 체크리스트
- [ ] 새 API가 `apiClient`를 사용했는가
- [ ] 요청/응답 타입이 정의되었는가
- [ ] `index.ts` export가 갱신되었는가
- [ ] 4xx/5xx 처리 경로를 호출부에서 다뤘는가
- [ ] 민감 정보 로그가 없는가

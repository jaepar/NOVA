# 인증서 약관 동의 규격 (v1)

이 폴더는 인증서 발급 단계의 약관 동의 페이지를 표준 방식으로 구현하기 위한 규격입니다.

## 1) 목표

- 페이지마다 약관 구조를 다시 설계하지 않는다.
- 팀원/AI가 동일한 데이터 구조와 상태 규칙으로 구현한다.
- 실제 약관 교체 시 데이터 파일만 수정해서 반영한다.

## 2) 필수 파일

- `spec.ts`: 약관 정의 타입 및 조회 유틸
- `storage.ts`: 동의/아코디언/캐러셀 상태 저장 API
- `definition.sample.ts`: 실제 약관 정의 교체용 샘플

## 3) 규격 필드

- `ConsentDefinition.domain`: `"certificate"` 고정
- `ConsentDefinition.version`: `"v1"` 고정
- `ConsentCategory`: `id`, `title`, `required`, `terms`
- `ConsentTerm`: `id`, `title`, `required`, `summary`, `content`

## 4) 인터랙션 규칙

- 큰 카테고리: 아코디언
- 세부 항목: 상세 페이지 이동 기반 동의
- 세부 체크 아이콘:
  - 체크됨 → 체크 해제
  - 미체크 → 상세 페이지 이동 후 동의
- 큰 카테고리 체크 아이콘:
  - 모두 동의 상태면 전체 해제
  - 하나라도 미동의면 카테고리 동의 페이지 진입
- 단건 상세 페이지 하단 버튼 텍스트는 항상 `동의하기`를 사용한다.
- 캐러셀 페이지 버튼(큰 카테고리 체크 아이콘으로 진입하는 다건 상세 슬라이드 페이지의 하단 고정 버튼) 텍스트는 항상 `모두 동의하기`를 사용한다.
- 카테고리 전체 동의 캐러셀은 진입 시 항상 첫 상세(1번)부터 시작한다.

## 5) 상태 저장 규칙

- 동의 상태: `getAgreedTermIds`, `setAgreedTermIds`, `markTermAgreed`, `markTermsAgreed`, `unmarkTermAgreed`
- 아코디언 상태: `getOpenCategoryIds`, `setOpenCategoryIds`
- 캐러셀 위치: `getCategoryCursor`, `setCategoryCursor`

`window.sessionStorage` 직접 접근 금지. `storage.ts` 함수만 사용.

## 6) 작업 절차

1. 구현 전에 아래 요구사항을 먼저 확인한다.
   - 선택 카테고리 개수
   - 각 카테고리(필수/선택)의 세부 약관 개수
2. `definition.sample.ts`를 복사해 서비스 도메인별 실제 정의 파일 생성
3. 약관 페이지에서 `spec.ts` 타입을 기준으로 데이터 바인딩
4. 상태 처리는 `storage.ts` API만 사용
5. 신규 규칙 추가 시 이 문서와 `frontend/AGENTS.md` 동시 갱신

## 7) 샘플 페이지 완료 기준

- 요청받은 카테고리 수(필수/선택)와 세부 약관 개수가 데이터에 반영되어야 한다.
- 세부 항목 상세 라우트가 동작해야 한다.
- 카테고리 동의 캐러셀 라우트가 동작해야 한다.
- 세부 체크 아이콘 규칙(해제/상세이동)이 동작해야 한다.
- 큰 카테고리 체크 아이콘 규칙(전체해제/캐러셀진입)이 동작해야 한다.
- 상세 페이지 하단 버튼 텍스트(`동의하기/확인`) 규칙이 동작해야 한다.
- 단건 상세 페이지 버튼 텍스트가 항상 `동의하기`인지 확인해야 한다.
- 카테고리 전체 동의 캐러셀이 항상 `1 / n`부터 시작하는지 확인해야 한다.
